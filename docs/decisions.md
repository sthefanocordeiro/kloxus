# Decisions

Running log of implementation decisions. When the spec is ambiguous, choose the
simplest option that keeps the zero-setup demo working and record it here.

| # | Date | Decision | Rationale |
| --- | --- | --- | --- |
| D1 | 2026-11-09 | SQLite via `modernc.org/sqlite` (pure Go, no CGO) instead of the PostgreSQL named in the README architecture table. In-process `jobs` table + ticker instead of a Postgres queue. | Judges must run the project with only Go installed; no external services allowed. README's architecture section is updated in M6. |
| D2 | 2026-11-09 | Demo mode is the default and runs fully offline: fixture feeds, replayed LLM responses, `.eml` files in `./outbox`, fake payment provider. | No API keys or accounts may be required to evaluate the project. |
| D3 | 2026-11-09 | Replay fixtures are keyed by a stable hash of (model, prompt template name, normalized input). Missing key = hard failure naming the key. | Makes fixtures deterministic and regenerable via `kloxus record`. |
| D4 | 2026-11-09 | The Anthropic client is built in milestone 2, before the `record` command is polished in milestone 4. | Replay fixtures can only be produced by real API calls; M2 cannot finish without them. |
| D5 | 2026-11-09 | Model IDs are configurable env vars. The spec's `claude-haiku-5-5` / `claude-sonnet-5-5` are placeholders to be verified against the API at integration time. | Model naming changes; never hard-code. |
| D6 | 2026-11-09 | All UI assets (CSS, htmx) are embedded with `go:embed`. No CDN links. | The UI must work offline. |
| D7 | 2026-11-09 | ~~No hosted deployment for the MVP~~ **Revised 2026-11-10:** a publicly hosted demo IS required — HackBrazil rules demand a working demo link that stays up through evaluation. We deploy the demo-mode binary itself to fly.io/VPS; the product remains fully self-hostable. | Submission rules §7.2–7.3 supersede the original spec's "no hosted server" assumption. The demo-mode build is ideal for hosting: replayed fixtures, embedded SQLite, zero keys, deterministic output. |
| D10 | 2026-11-10 | Rejected re-architecting the demo to serverless + Postgres/Supabase (Vercel/Netlify path). Postgres is deferred to the post-pilot SaaS phase. | Serverless can't run a persistent process with a writable FS; would need dual SQL dialect, function adapter, timeout chunking, and Supabase free tier pauses after ~7 days idle — a mid-evaluation outage risk. ~2–4 days of work for zero judge-visible gain. |
| D11 | 2026-11-10 | Interactive-path LLM calls (editorial-guide rebuild, "alternative" suggestions) get deterministic fallbacks when no replay fixture matches; pipeline-path calls (triage…citecheck) fail loudly instead. | Judge interactions are arbitrary input — no fixture can cover them. The fallback keeps the demo honest and working; real mode always uses the model. |
| D12 | 2026-11-10 | Deep dive is a single batched model call in demo mode (top-3 items); the per-item bounded tool loop is real-mode only. | A demo tool loop would need recorded tool outputs, doubling fixture surface for no visible gain. |
| D13 | 2026-11-10 | `stories` are rebuilt from scratch every run; old `issue_items` keep a dangling `story_id`. | Dedupe output must be identical across runs for replay keys to stay stable. Old issues are self-contained in `dossiers` and `body_md`. |
| D14 | 2026-11-10 | Firecrawl integration: `/monitor` API for `type: page` sources without RSS (real mode), `scrape` endpoint stays the immediate-fetch fallback; `MonitorProvider` interface with a simulated demo badge; webhook `POST /webhooks/firecrawl` + "Check now" polling fallback for localhost. | Firecrawl sponsors HackBrazil (5,000 credits). The original spec scoped it to extraction only because no hosted server was assumed; with a public instance, monitoring is the better fit. Crawl/website monitors stay out of scope. |
| D15 | 2026-11-10 | In replay mode, PhaseB sends the canonical all-selected item set to draft/citecheck regardless of review decisions, then filters the stored body and flags to non-rejected items. Real mode keeps active-only input. | Judge decisions are arbitrary and must not change fixture keys. The canonical prompt reuses the recorded full-issue draft/citecheck responses while preserving the editor's selected issue. |
| D16 | 2026-11-10 | Demo reset is serialized against pipeline runs with a `sync.RWMutex` (runs take read lock, reset takes write lock), and `DB.Reset` clears `sqlite_sequence` so the reseeded publication always gets id 1. | A hosted reset must not wipe data mid-run; stable ids keep deep links (`/pub/1/...`) valid across resets without a config-level id. |
| D8 | 2026-11-09 | Reader payments go through the creator's own AbacatePay account; Kloxus stores a restricted, AES-256-GCM-encrypted key and never holds money. | Editorial principle: readers pay the creator, not us. |
| D9 | 2026-11-09 | Fixture articles are fictional and original, written for this repo, with fictional outlets. No real article text is committed. | License safety and a clear conscience for the curation-is-not-reproduction principle. |
| D17 | 2026-11-11 | Hosted demo runs multi-workspace: `KLOXUS_DATA_DIR` switches to one SQLite file per visitor (signed-cookie id), cloned from a seeded `template.db`; LRU handle cache + idle-age cleanup + per-IP create rate limit. | Each judge gets an isolated, persistent demo without accounts; a reset affects only that workspace. |
| D18 | 2026-11-11 | Visitor-added sources are stored but never fetched in demo mode; `FixtureFetcher` is the only fetcher and collect skips non-`fixtures/` URLs. | Public-source-addition on a public instance is an SSRF surface; simulation keeps the feature visible and safe. |
| D19 | 2026-11-11 | Fixture content is fully fictional (Valdória: BCV, Lume, Autoridade da Concorrência, Universidade de Porto Alto, Consórcio Lumen) on reserved `.example` domains; article links are served by the app at `/a/{item}`. A denylist test (`TestFixturesAreFictional`) guards it. | Demo must not present real institutions/companies/people as covered news; app-served articles keep every link clickable offline. |
| D20 | 2026-11-11 | Issue body stores only reader content (no score/reason/commentary placeholders); commentary lives in `issues.commentary_json` and `delivery.ReaderBody` composes the final output per surface. Internal data is filtered deterministically, never by prompt promises. | Reader-facing output must never leak review metadata or helper text. |
| D21 | 2026-11-11 | v2 milestone 1: `/api/v1` is a thin JSON layer over the existing handlers — same workspace cookie, same rules, no new schema beyond `approval_receipts`. The issue document is parsed from `body_md` (sections/items/sentences, `<!-- item N -->` markers = dossier refs); sentence ids are `{itemRef}.{hash}` over the stored text so edits can't silently hit a sentence that shifted position, and every document mutation must send back the document `version` (stale → `409 conflict` + fresh document). A test `send` only records the outbox email — the issue stays `approved`; only a `readers` send marks it `sent`. Approvals persist a receipt (document version, approver = workspace label, checks, timestamp); post-approval edits void it. Draft (Phase B) is an async run like prepare, so `/runs/{id}/events` (SSE, real counts, no percentages) covers both. `send` requires an explicit `audience` (safe default: none). Preview `surface` is accepted but presentation-only. Flags that match no single sentence stay on the item. | Front end needs one contract; re-parsing the canonical stored body keeps the server the single source of truth — the interface shows state, never decides it. Async draft unblocks the UI during real-mode model calls. Safe-default audience matches the product rule that nothing is sent without explicit choice. Hash-anchored ids + version keep editor mutations honest without a stored document model. |
| D22 | 2026-11-12 | v2 milestone 2: the new interface is React + TypeScript + Vite, built to static files in `internal/web/appdist` and embedded with `go:embed` — served at `/app` (SPA fallback to index.html, immutable hashed assets), no Node server or CDN in production. Design tokens (`@theme`, Tailwind v4) are the single styling source; fonts are bundled via @fontsource. The editor renders the API document through Tiptap custom nodes — sentence (atom, with citation chips + flag actions), itemHeading, commentary (the only editable region; autosave PUTs with the document version) — so the server stays the source of truth and AI output is never presented as creator text. UI chrome ships EN + pt-BR ("pauta"); publication content keeps the creator`s language. | Front-end-first on the working backend: the API contract decides what can be done, the client only displays and invokes it. Embedding keeps the single-binary deploy; /app alongside the htmx pages lets the fallback survive until milestone 4. |
| D23 | 2026-11-12 | v2 milestone 4: the approve step is an "Approve & send" dialog (audience default "Nobody (test only)", send-now vs schedule, document version, sourced count, sender). `send` accepts `when: now|schedule` — scheduling applies only to a reader send and marks the issue `scheduled`, locked like `sent` but with no outbox dispatch (demo has no clock); `POST /issues/{id}/hold` is the only way back and reuses `RevertIssueToDraft` (re-approval required). Reader-facing surfaces are React routes outside the editor shell: `/app/p/{slug}/{num}` (public issue, gated body for non-subscribers, magic-link `key` unlock, `view=free` preview) and `/app/unsub` (one-click unsubscribe via `GET /api/v1/unsub`); short `/p/...` URLs redirect there and every email link now points into the app. `?ws=` workspace resolution (shared `withWS` helper) lets reader links open in any browser. `GET /issues/{id}/after` powers the after-sending view (public URL, exports, receipt, rules the guide learned). The root serves the React app (`/` → `/app/`); the htmx fallback stays reachable via `/classic` as its entry point — its internal pages keep their existing paths, recorded as the simplest interpretation of "reachable under /classic". | The reader journey is part of the product story for judges — it deserves the same design, not the fallback's plain templates. `scheduled` with Hold demonstrates the full send lifecycle without inventing a dispatch clock; requiring re-approval after Hold keeps the receipt honest. Keeping htmx URLs unchanged avoids rewriting every template link for a fallback that ships in weeks. |
| D24 | 2026-11-12 | v2 milestone 5 (onboarding): hosted workspaces start EMPTY — the template is schema-only and `publications.custom` distinguishes creator-made rows; the seed-refresh on workspace open only reseeds canonical pubs, and reset returns to empty so the visitor re-walks onboarding. The flow is landing (`/` → cited sample dossier, workspace-free via `GET /api/v1/sample`) → `/new` (proposal → five editable blocks; paste-a-link refused with `live_only` in demo) → `POST /publications` (stores `custom=1`, slug deduped) → `/pub/:id/sources` (catalog of fixture sources, real 3-item previews via the fetcher, pasted URLs format-validated but never fetched, delete cascades story_items+items in a tx) → confirm + auto first run. **Canonical substitution at read time**: demo fixtures replay by prompt hash, so for `custom` publications every prompt/section-bearing load (`canonicalPub` wrapping `GetPublication` + `s.pub`) swaps topic/audience/editorial_line/tone/sections for the sample's — stored edits stay visible in the detail view while runs, capacities, document building and guide rebuilds use canonical text. `kloxus demo` (UI) starts empty; only `--headless` seeds. The no-JS fallback gets `POST /classic/seed` since htmx can't walk onboarding. | Making onboarding the first screen turns "what is this" into a product story — the cited sample dossier sells the invariant before a workspace even exists. Canonical substitution is the only way to keep fixture replay deterministic while letting creators edit the definition; scoping it to prompt-bearing fields (not name/slug/paywall) keeps every display honest. Headless-only seeding preserves the canned pipeline path for CI and `demo --headless` evaluators. |
| D25 | 2026-11-12 | Review fixes after M5 deploy: **paywall root cause** — config structs had only yaml tags, so JSON-created (custom) publications silently dropped paid_sections/editorial_line/ai_disclosure and every reader output rendered ungated; json tags added, plus a regression test gating both the public page and the readers email on a custom pub. Reader links stop carrying the workspace id: PublicToken AES-256-GCM seals it as ?tok= (withWS resolves tok and legacy ws), and all emitted links (public_url, magic link, unsubscribe) moved to root paths. The SPA now owns / via the Go catch-all (old /app/* 301s); React pub routes renamed to /publications/* so htmx keeps /pub and /issue. Learned rules generalize: chips map to standing rules ("too early" → "Skip stories that just broke…"), the story title only feeds the LLM prompt, and `after` returns the same RulesFrom output. Reader outputs localize via localizeReaderMD (canonical section headings swap for the creator's titles, **Sources:** → **Fontes:**); the reader page drops the duplicated H1 and renders _italics_. Sends confirm through a dialog (subscriber count from new SubscriberCount, subject, sender) and answer to/subject so the test-send toast names its destination; toasts expire at 8s and pending Undos clear on status change. Sources screens show outlet name + type (SourceDef.name backfills sources.name); the landing sample is fully fictional (UDV, *.example domains, app-served stub articles at /sample/a). | Gate-then-localize keeps fixture replay (canonical text) compatible with per-creator display; the sealed token hides the workspace id without a lookup table or new state. Generalizing chips in code — not via the LLM — keeps the invariant that guide rules never parrot headlines and stay deterministic under fixtures. |
| D26 | 2026-11-13 | Review fixes, second pass: **no more 301s on the app shell** — /app/* serves the SPA with 200 and the client strips the prefix (browsers had cached the old / -> /app/ 301, so any 301 back loops forever). Editor headings are non-editable atoms (sectionHeading, itemHeading carry their text in attrs; selectable:false), so typing can no longer leak into titles; the commentary card focuses its content on any click outside the editable text. Sources onboarding is a checkbox list: pre-checked fixture cards with outlet name + items_per_week (catalog computes it from the fixture fetch), confirm posts {"include": [...]} so the count always matches the selection, and sourceAdd accepts a name for own sources. The send dialog reads "N readers (M paying)" via new store.ReaderCount next to SubscriberCount, radio groups sit in fieldset/legend for screen readers, and localizeReaderMD translates the AI-disclosure line for pt publications. | A cached permanent redirect is forever for a demo URL judges may revisit — serving 200 with a client-side path fix is the only fix that does not depend on cache busting. Atoms for headings encode the invariant (AI text is never user-editable chrome) in the schema, not in styling. |
| D27 | 2026-11-12 | **Amends the "non-negotiable" constraints, D2, D6 and D23.** The submission target is a hosted real app; judges are not required to run anything locally. The classic htmx UI is deleted and React is the only interface. The fake providers (replay LLM, outbox mailer, fake monitor, fake payments) stay as the test bed and as the runtime fallback when a real service fails or a cap is hit. The current fixture demo is tagged and kept deployed as the fallback URL; the real app is a separate Fly app. | Two implementations of the same rules already produced a bug (review F6: a scheduled issue still accepts decisions through classic). Keeping fakes preserves offline tests and a safe degradation path. |
| D28 | 2026-11-12 | **Supersedes D1 and D10.** Storage moves to Postgres on Supabase Free, used as plain Postgres only (no Supabase auth, RLS client or edge functions); the Go binary stays on Fly. One shared schema with `workspace_id` on every tenant table replaces one SQLite file per visitor (D17). One SQL dialect only. Article bodies are dropped after 30 days (500 MB limit); a nightly `pg_dump` runs from GitHub Actions (no free backups). Time-box: if the port is not green by Nov 17, fall back to SQLite + Litestream. | D10's objection was serverless, which no longer applies. Shared Postgres removes review findings F1 (path traversal) and F4 (handle eviction) and makes a global scheduler and durable runs simple. The free-tier pause (1 week idle) is avoided by the feed scheduler's own writes. |
| D29 | 2026-11-12 | Ingestion is split from editorial work. Feeds are fetched once, globally, with no LLM; each workspace pays only for its own editorial run. Sources live in a seeded `source_catalog` with a policy per source (`launch`, `signal`, `hold`, `blocked`); the code refuses to fetch anything not `launch` or `signal`. Launch catalog (full-text RSS): Tecnoblog, Olhar Digital, TabNews, MacMagazine (root feed only, 10 s delay), Meio Bit, Startups.com.br. Signal only (links, no content): Hacker News. Blocked or held sources are not fetched and not worked around (no Feedburner mirror, no `wp-json`). Robots is re-checked daily and a newly disallowed source suspends itself. **Amends D18:** anonymous workspaces pick only from the catalog; custom URLs require a claimed workspace plus SSRF guard and robots check. | Based on the owner's source audit of 2026-11-12. A global fetch keeps cost flat as workspaces grow and respects each publisher's stated rules. |
| D30 | 2026-11-12 | Topic discovery = LLM query expansion + keyword search, ranked by the existing triage step. Providers: Firecrawl Search (`sources: ["news"]`, 5k-credit coupon) and the Daily Journal public API (D31). Blocked catalog domains are passed as `excludeDomains`; anything outside the catalog is links only. Searches are capped per workspace. Exa (semantic) and pgvector over our own items are post-hackathon. | Uses the sponsor coupon on something judges can see, needs no new vendor, and keeps the source policy intact. |
| D31 | 2026-11-12 | Daily Journal (dailyjournal.news) joins the catalog as a `signal` source through its public API only (`/api/public/news`, no auth). We store title, description, categories, `outlet_count`, `source_count`, the Daily Journal URL and the cited source links. We never ingest its body as evidence, never scrape its HTML, and never present its AI-written summary as a quote from an outlet. Polling: one cursor poll every 15 minutes, detail calls on demand, hard cap 350 requests a day (their fair-use ask is about 30 a minute and 400 a day per client). Written confirmation from the founder is requested before launch. | Their terms (2026-11-03) and `llms.txt` ask automated clients to use the API or MCP, welcome citation with a link, and ask not to republish the set of summaries without talking to them. Its stories are pre-clustered across Brazilian outlets with real ISO dates, which is the ranking signal the RSS catalog lacks. |
| D32 | 2026-11-12 | Real LLM calls are guarded: per-workspace run budget, global daily cap with a kill switch, retries and panic recovery. When a cap is hit the app serves the recorded sample instead of failing. A second provider is added behind the existing `Provider` interface as a generic OpenAI-compatible client (base URL, key and model names from env). One real issue is recorded as replay fixtures for the landing sample. | Anonymous visitors can now spend money (review F3). The owner's zero-cost LLM option still needs its endpoint confirmed and must pass the quality gate (six prompt steps return valid JSON, citecheck catches planted errors, pt-BR draft acceptable). |
| D33 | 2026-11-12 | Email goes through Resend from `kloxus-ai.trendfi.com.br`, with a sending-only key restricted to that domain. Email is sent only to confirmed addresses, capped at 80 a day globally (free limit is 100 a day, 3,000 a month) and per workspace. A workspace starts anonymous (signed cookie) and is claimed by a magic link sent to the creator's email; that confirmation is the auth model. | An anonymous app that sends email is an abuse vector; confirmation gives us auth without a password system. |
| D34 | 2026-11-12 | Checkout is readers paying a creator (D8 stands as the pilot target). For the hackathon a single Kloxus test-mode AbacatePay key is used. If AbacatePay has no recurring billing, we sell 30-day access as a one-time PIX payment. First item cut if the schedule slips. | Demonstrates the paywall end to end without asking judges or creators for payment accounts. |
